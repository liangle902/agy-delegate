# agy-delegate 调用说明（通用，适用于任何主代理）

本文件说明怎么让**任意主代理（或脚本）**通过运行器 `agy_run.py` 驱动本机的 Antigravity CLI（agy）干活。
文中的**调用方**指主代理或脚本，**agy** 指被驱动的执行者。本文不假设调用方是哪个产品；和具体产品有关的做法都放在 `adapters/` 目录里。

> **第一次在这里用？** 先看第 11 节：检查 `adapters/` 里有没有你的适配层；没有就按那一节的规程自己补一份。

## 1. 它解决什么问题

调用方把脏活累活（批量改代码、补测试、按明确方案实现功能、机械性重构、跑验证、独立审计、批量数据清洗、OCR）交给本机 agy 执行，用的是本机已登录账号的额度。

- **调用方**：澄清需求、定方案、写任务书、监控、纠偏、验收、向用户汇报。
- **agy**：按任务书执行。它看不到调用方的上下文，**任务书必须自带全部信息**。
- **几行就能改完的事调用方直接改，不要派**：一次派发的固定开销（任务书 + 起步约 1.3 万 token + 验收）比改动本身大。
- **不适合派的**：需求还没澄清；需要生产环境凭据；不可逆操作。

**所有调用都经过运行器，不要直接拼 `agy` 命令。** 运行器替你做了：结果重新判定（agy 自己报的成功不可信）、全量落盘、卡死自动终止、项目复用与清理、额度预检、可续接的现场保留。

```
python <本文件所在目录>\agy_run.py <quota|run|wait|watch|status|list|result|kill|gc|selftest>
```
下文用 `<RUNNER>` 代表这条命令的前半截。

## 2. 两种监控方式（按你的能力二选一）

| | 模式 A：事件流 | 模式 B：后台 + 等待 |
|---|---|---|
| 适合 | 能把长命令放后台、并且**输出一行就唤醒你**（有类似 Monitor 的工具） | 只能"执行一条命令、等它返回"，没有输出行唤醒 |
| 启动 | `<RUNNER> run ...`（前台跑到结束，输出的 ALERT/WARN/END 行就是事件） | `<RUNNER> run ... --detach`，立刻返回 `STARTED run=<运行名>` |
| 取事件 | 工具把每一行推给你 | 反复调用 `<RUNNER> wait <运行名>`，每次阻塞到下一批事件 |
| 结束信号 | 看到 `END` 行 | `wait` 返回 END 对应的返回码 |

两种方式事件内容完全一样。**拿不准就用模式 B**：它只需要"执行命令并读返回"这一个能力。

## 3. 命令参考

### run（派发一个任务）
`<RUNNER> run --cwd <目录> --prompt-file <任务书> --name <短名> [选项]`

| 选项 | 含义 |
|---|---|
| `--cwd` | 真实的项目目录。**同一仓库的不同任务用同一个目录**（项目按目录复用） |
| `--prompt-file` / `--prompt` | 任务书（建议文件） |
| `--name` | 运行名后缀，便于辨认 |
| `--timeout` | `5400`（裸数字按秒）/ `90s` / `30m` / `2h` / `1h30m`，默认 30m。写错在启动 agy 之前就报错退出（返回码 2） |
| `--resume <会话ID>` | 续接上次的会话（见第 8 节） |
| `--plan` | 只读规划模式，不改文件。注意：该模式下 agy 的命令执行会被拒绝 |
| `--model` | 默认 `gemini-3.8-flash-high`；`--effort low/medium/high` 现在可以和它同用（运行器自动处理模型名后缀） |
| `--detach` | 后台启动（模式 B） |
| `--stdout act\|all` | 默认 `act`：只输出 ALERT/WARN/END；`all`：恢复完整输出（START/INIT/RESULT/FINAL/HEARTBEAT…） |
| `--notify-cmd <命令>` | 额度/登录告警时由运行器自己执行（见第 6 节）；也可用环境变量 `AGY_NOTIFY_CMD` |
| `--expect <路径>`（可重复） | 声明任务应当写出的文件；任务书表格里反引号包着的输出路径也会自动识别（`--no-auto-expect` 关闭） |
| `--auto-resume N` | 瞬时 API 错误/登录到期时自动续接的次数，默认 1，0 关闭 |
| `--throwaway` | 一次性运行：结束后删本次新建的项目和会话，之后不能续接。**临时目录、试验必须加**。可以和 `--detach` 同用，**不能**和 `--resume` 同用 |
| `--no-quota-check` | 跳过额度预检 |
| `--stall-think` `--stall-cmd` `--think-kill` `--cmd-kill` `--cmd-quiet` `--idle-kill` `--loop-kill` `--progress-window` | 自动终止的阈值，默认值见第 7 节；`--stall N` 是旧参数，现在只当"首次告警的下限" |

### wait（模式 B 取事件）
`<RUNNER> wait [<运行名>|latest] [--timeout 秒] [--until alert|end]`

只显示**上次 wait 之后**新出现的 ALERT/WARN/END 行。运行如果自动续接成了新运行，会自动跟过去（输出一行 `CHAIN a -> b`）。返回码：

| 返回码 | 含义 | 你该做什么 |
|---|---|---|
| 0/2/3/4/5 | 看到了 `END`，就是这次运行自己的返回码（见第 5 节） | 进入验收/处理 |
| 10 | 有新告警，运行仍在继续 | 按第 5 节的表处理，再调一次 wait |
| 11 | 到点没有新事件，运行仍在跑（`WAIT_TIMEOUT`） | 没事，再调一次 wait |
| 12 | 运行器已不在且没有 END（`WAIT_ORPHANED`，崩溃或被强杀） | 用 `status`/`result` 看现场，决定续接 |
| 运行自己的返回码（0–5），输出里是 `WAIT_FINISHED` | 运行早已结束，事件已被取走（对已结束的运行再调 wait 就是这样） | 用 `result` 读结果 |

**注意**：10、11、12 **只会出现在 `wait` 里**，`run` 本身的返回码只有 0–5。`--timeout` 的单位是**秒**，要小于你工具的单次命令上限（建议留 20 秒余量）。**返回码 10 不一定出事**：有些告警（比如模型思考时间长的 `STALL`）看一眼就知道不用处理，确认后再调一次 wait 即可。

`--until end`：告警只显示、不返回，一直等到 END（适合调用方不想被告警打断的场景，但"有告警必须当次处理"的规矩仍然适用）。

### 其他命令
- `watch [<运行名>|latest]`：**给人看的**实时视图，跟随 `digest.log` 到运行结束。
- `status [<运行名>] [--lines N]`：状态和最近 N 行摘要。
- `list [--running] [--since 天数]`：列出运行，状态为 `RUNNING` / `ORPHANED`（运行器已不在）/ `finished` 等。
- `result [<运行名>]`：打印 `result.json` 的内容和汇报全文。
- `kill [<运行名>]`：终止一个运行；结果记成 `KILLED_MANUAL`（返回码 4，可续接）。
- `quota [--model ...]`：查剩余额度，**零 token**。
- `gc [--dry-run]`：清理没有会话的空项目（目录不存在或重复）。先 `--dry-run` 看会清什么。
- `selftest [--live [--detach]]`：检查环境能不能用（见第 11 节）。`--live` 会跑一个最小真实任务；`--live --detach` 把它放后台、立刻返回，给单次命令有时间上限的调用方用。

## 4. 标准流程

1. **写任务书**（第 9 节），存成文件，用 `--prompt-file` 传入。
2. **隔离**：在 git 仓库里干活，动手前工作区要干净（或开 worktree/分支），这样验收就是看 diff。审计、验证类任务用独立的审计 worktree。
3. **启动并监控**：模式 A 或模式 B。长任务注意你的工具有没有单次命令的时间上限（有的监控工具上限只有 30 分钟），超过就改模式 B，或者到期后重新挂上同一条命令——运行不受影响。
4. **按事件处理**（第 5 节）。**没有告警时不要评论进度**：每个事件都可能让你重读整段上下文，这是调用方侧 token 开销的大头。想看过程的用户用 `watch`。
5. **有告警时必须当次处理完**：先 `status <运行名> --lines 40` 看上下文，决定"继续等"还是"杀掉续接"，并用一句话告诉用户发生了什么、你做了什么决定。"继续等"对同一件事只能选一次；同一条命令第二次 STALL、或任何 LOOP 类告警第二次出现，就直接 `kill` 后续接。
6. **结束时先回一句**"已结束，正在验收"，再去核实。
7. **验收**：`verdict=DONE_UNVERIFIED` 只表示 agy 自称完成。必须：通读生产代码的 diff，确认逻辑符合任务书、没有超范围改动；用项目锁定的工具链自己重跑改动文件的静态分析和相关测试；`git status` 和 `git diff --cached` 确认没有多余文件、没有擅自提交、**暂存区没有被动过**，清理临时文件。**agy 汇报里的数字（测试通过数、覆盖率……）都要自己重跑核对**。
8. **汇报**：结论先行；附上额度（`END` 行的 `q5h`，或 `result.json` 里的 `quota_after`）、用时、用量；明确写出没验证到的部分。
9. **提交、推送、改 PR 描述等对外动作**：等用户发话。让 agy 提交时，任务书里写明逐个 `git add` 指定文件、禁止 `git add .`、不 push。

## 5. 输出协议

默认模式下运行器的标准输出只有三类行（`--stdout all` 才有更多）：

- `ALERT <类型> <说明>`：需要你决定或知晓的事件。
- `WARN <说明>`：值得知道但不必立刻动作。
- `END run=<运行名> verdict=<结论> rc=<返回码> dur=… tok=… files=… cmds=… q5h=…% [resets_in=…] [note=…] [missing=…] result=<result.json 路径> [resume: <续接命令>] final="<汇报前 120 字>"`：**每个运行必有且只有一行**（自动续接的中间态不推），之后读 `result.json` 拿全部细节。

### ALERT 类型与处理
| 类型 | 含义 | 处理 |
|---|---|---|
| `QUOTA` / `QUOTA_LOW` / `AUTH` | 额度不足或登录失效（`QUOTA_LOW` 是启动前预检没通过，没启动 agy） | **必须通知用户换账号重新登录**（换号只能用户做）。配了 `--notify-cmd` 运行器已经自己通知了，你仍要在回复里告诉用户。然后停下，不要重试 |
| `ASK` / verdict `NEEDS_INPUT` | agy 想提问，无头模式下被自动跳过 | 读 `result.json` 里的汇报；自己能答就 `--resume` 回答，否则问用户 |
| `DENIED` | 有操作因权限被拒 | 检查是否误用了 `--plan` |
| `PRINT_TIMEOUT` | agy 自己的 `--print-timeout` 到点，只返回了半截输出 | 任务没做完，用 `--resume` 继续（verdict 会是 `TIMEOUT_PARTIAL`） |
| `LOOP` | 同一调用且输出相同、期间没改文件 | **先看 `status` 再决定**。重复执行同一条失败命令才是死循环，直接 `kill` 续接 |
| `LOOP_EDIT` | 改了文件，但同一条命令的失败结果不变 | 改了等于没改。`kill` 续接，纠偏提示里要求它先定位原因再动手 |
| `NOPROGRESS` | 一个窗口内工具调用不少，却没有新调用、工作区没变 | 第一次出现就看 `status`，多半该 `kill` 续接 |
| `STALL` | 长时间没有新事件 | 看"当前"是什么：模型思考中且时间不长可以等；命令本该几秒却卡住就 `kill` 续接 |
| `AUTOKILL` | 运行器已经自己把 agy 终止了，原因写在这一行 | 不要原样重跑。先回用户一句，再看 `status`，按续接命令续接，纠偏提示里写明被终止的原因和不许再做的事 |
| `DRIFT` | agy 的事件格式、权限模式或模型和预期不符（多半是 agy 升级了） | 结果多核对一遍，并告诉用户 |
| `SANDBOX` | 命令在 agy 终端沙箱里失败 | 提醒用户在 agy 的 `/config` 里关掉 Sandbox Mode |
| `AGY_EXITED_EARLY` | agy 在读到任务书前就退出了 | 看 `status` 里的 STDERR 行 |
| `TIMEOUT` / `HEARTBEAT` | 总超时；或"工具调用不少却全是旧调用"的空转心跳 | 看 `status`，决定续接还是拆小任务 |

**不再推送的提示**：agy 启动慢（INIT 之后很久没有第一个步骤，多半在等某个 MCP 服务器连接）**不会**作为 ALERT 推给你，因为它不需要处理。总耗时在 `END` 行的 `slow_start=Ns` 和 `result.json` 的 `flags.slow_start_s`，是哪个 MCP 服务器在拖慢在 `flags.slow_start_detail`，明细在 `digest.log` 的 `SLOW_START` 行。同一个服务器反复拖慢启动时，提醒用户去 agy 里关掉它（只有用户能改 agy 的设置）。

### verdict 与返回码（`END` 行和 `result.json`）
| verdict | rc | 含义 |
|---|---|---|
| `DONE_UNVERIFIED` | 0 | agy 自称完成，**未验证**，必须验收。`note=` 可能带 `api_error_recovered`（agy 内部重试后恢复）或 `timeout_but_outputs_complete` |
| `DONE_PARTIAL` | 4 | 自称完成，但任务书清单里有输出文件没写（`missing=` 列出缺的） |
| `TIMEOUT_PARTIAL` | 4 | agy 自己的 print-timeout 到点，半截输出。续接 |
| `NEEDS_INPUT` / `DENIED` | 2 | 需要人工 |
| `QUOTA` / `AUTH` | 3 | 额度或登录问题，需要用户 |
| `ERROR_AUTH` / `ERROR_TRANSIENT` | 5 | 登录到期 / 服务端瞬时错误。默认已自动续接一次，仍失败才会作为终态出现（AUTH 再失败会变成 `AUTH`，返回码 3） |
| `ERROR` / `EMPTY_RESPONSE` | 5 | 其他错误 / 回复为空 |
| `KILLED_LOOP/NOPROGRESS/STALL/TIMEOUT` | 4 | 运行器自己终止了 agy，成果和会话保留，可续接 |
| `KILLED_MANUAL` | 4 | 被 `kill` 子命令终止 |
| `NO_RESULT` | 4/5 | agy 没给出结果就退出了（崩溃或被外部杀掉） |
| `BAD_ARGS` | 2 | 参数错误，没有启动 agy |
| `RUNNER_<异常名>` | 5 | 运行器自己出了异常（agy 已被清理，记录标为 `crashed`） |

返回码约定：0 自称完成（未验证）/ 2 需要人工 / 3 额度或登录 / 4 超时、被杀、可续接 / 5 其他错误。

## 6. 主动通知（`--notify-cmd`）

额度、登录这类必须有人处理的告警（`QUOTA`、`QUOTA_LOW`、`AUTH`），运行器可以**自己**执行一条命令通知用户，不依赖调用方有没有通知工具：

- 用 `--notify-cmd "<命令>"` 或环境变量 `AGY_NOTIFY_CMD`。命令经 shell 执行，不显示窗口，失败被忽略，不影响运行。
- 命令里可以用环境变量：`AGY_ALERT_KIND`（类型）、`AGY_ALERT_MSG`（说明）、`AGY_RUN_ID`、`AGY_RUN_DIR`。
- 登录到期但自动续接成功的情况**不会**通知（不打扰人）。
- 示例（Windows 弹气泡通知用你自己的方式）：`--notify-cmd "msg * /time:30 %AGY_ALERT_KIND% %AGY_ALERT_MSG%"`。

没有配通知命令时，调用方必须在自己的回复里把这类告警明确转告用户。

## 7. 自动终止（运行器自己判定，不依赖调用方）

满足下面任一条就终止 agy，返回码 4，已有成果和会话都保留：

| 情形 | 默认阈值 | 开关 |
|---|---|---|
| 模型思考中无事件 | 首次告警 420 秒，之后翻倍退避，**900 秒**终止（agy 自己 5 分钟取消重试，所以不会太早） | `--stall-think` `--think-kill` |
| 命令执行中无事件 | 首次告警 600 秒；**进程树 CPU/IO 连续静默**超过 `--cmd-quiet`（默认 600 秒）判挂死终止；无条件 **3600 秒**终止 | `--stall-cmd` `--cmd-quiet` `--cmd-kill` |
| 同一调用且输出相同、期间没改文件 | 命令类 3 次告警、9 次终止；**读文件/轮询类 18 次告警、54 次终止** | `--loop-kill 0` 只告警不终止 |
| 同一段话重复 | 3 次告警、9 次终止（两次之间做过新的事会清零） | 同上 |
| 改了文件但同一条命令仍失败且结果不变 | 4 次告警、12 次终止（"0 errors"之类不算失败） | 同上 |
| 空转（窗口内没有新调用、工作区没变） | 连续 2 个 8 分钟窗口 | `--progress-window` |
| 总时长 | `--timeout` + 60 秒 | `--timeout` |

`--idle-kill N` 同时覆盖思考和命令两种"无事件终止"阈值，0 为不杀。这些判定只看形式，不懂任务：任务本身就是重复性的（按清单逐个跑同一条命令，只是参数不同）不会误伤，但"反复跑同一条命令等外部状态变化"会被当成死循环，这类等待不要交给 agy。

任务里确实有超过 10 分钟不出任何输出的单条命令时，才调大阈值，并在任务书里写明是哪条命令。

## 8. 干预与续接

- 运行中插话不可行（消息排到回合结束才处理）。干预方式只有：`kill`，然后 `run --cwd <同一目录> --resume <会话ID> --prompt "<纠偏或回答>"`。续接是可靠的，agy 会先盘点已有成果再继续，不会重做。
- 会话 ID 在 `END` 行的 `resume:` 命令里，也在 `result.json` 的 `conversation_id`。
- 纠偏提示要写：发生了什么、已有成果还在不要重做、怀疑的原因、接下来的硬性要求。被自动终止后的续接，还要点名那条命令或那处修改，并写"不许再原样执行它"。
- **同一个任务被自动终止两次，就不要第三次续接**：把任务拆小，或者这一段由调用方自己做，并告诉用户。
- 同一业务线的后续任务也用 `--resume` 续接同一个会话，省掉重新探索代码库。但会话越长每次重读上下文越贵，长会话要适时新开。
- **只能续接命令行自己建的会话**。Antigravity 桌面端的会话（`~/.gemini/antigravity/`）用 `--resume` 会报 `trajectory not found`；要接手桌面端的工作，新开会话，任务书里写明旧会话记录 `~/.gemini/antigravity/brain/<会话ID>/.system_generated/logs/transcript.jsonl` 的位置，让 agy 按关键词搜索而不是整个读。
- `--resume` 的会话在原来的目录里工作，`--cwd` 和它不一致时运行器会 `WARN`。

## 9. 任务书怎么写

必须包含：

- **背景**：当前目录是什么、哪个分支、项目类型；动手前要完整阅读的文件清单。
- **要做的事**：每个问题写清现象、代码位置、期望行为。给出修复方向并写明"有更简单的等价做法可以用，但要在汇报里说明"。
- **工具链**：先查项目是否锁定了版本（`.fvmrc`、`.nvmrc`、`.tool-versions`、`rust-toolchain` 等），在任务书里写死命令前缀。不写的话 agy 会用 PATH 里的版本，结论全错。
- **完成标准**：逐条列出要跑的确切命令和期望结果，包括已知的基线。
- **约束**（按需取用）：
  - 只改与任务直接相关的文件，不做顺手重构，不动生成文件；
  - 不 commit、push、切分支、stash、reset、clean；不执行依赖安装/升级；
  - **不要改动 git 暂存区**：不要 `git add`，也不要用 `git checkout <ref> -- <文件>` 或 `git restore --staged`（前者会把文件放进暂存区）；需要把某个文件恢复成某个版本，用 `git show <ref>:<路径> > <路径>`；
  - 不要向我提问，需要决策时选最保守的做法并在汇报里列出（无头模式下提问会被跳过）；
  - **所有测试命令带超时**，"单条命令超过 3 分钟没结束就视为失败，停下来分析"；
  - **防死循环**（原样写进任务书）："同一条命令连续 3 次得到相同的失败，就停止重试：换一个思路，或者停下来在汇报里写明卡在哪里。不要反复做同一处修改。不要对整个磁盘、用户目录或包缓存目录做递归搜索。监控程序发现重复或长时间没有任何输出会直接终止你。"
- **输出清单**（强烈建议）：任务要写出多个文件时，在任务书里放一张 markdown 表，把每个输出路径用反引号写出来，运行器会据此核对有没有漏写（`DONE_PARTIAL`）。
- **汇报格式**：限定行数；要求给出每条完成标准的命令和最后一行输出、改动文件清单、没做到和不确定的点。每开始一个阶段、每次做出决定时，先用一两句话说明要做什么、为什么（`watch` 里给人看的就是这些）。

审计类任务额外要求：每条问题必须带文件、行号、代码片段、触发条件；没有证据的放"待确认"；说明项目的目标平台。

## 10. 项目、会话与记录

- agy 每新建一个项目，就在 `~/.gemini/config/projects/` 留一个文件，并出现在桌面端侧栏。运行器**按 `--cwd` 复用已有项目**，同一个目录永远只有一个项目；"本次建的项目"靠会话里的项目 ID 认领，不会误认并发运行的项目；同一目录同时首次启动有锁，只会建一个。
- **一次性目录必须加 `--throwaway`**（只删自己建的）；`--throwaway` 不能和 `--resume` 同用。
- 删目录或 worktree 之后跑一次 `gc`。它不碰桌面端自建的项目，也不碰有会话的项目。
- **运行记录**默认在 `~/.claude/agy-runs/`（该目录已存在时），全新安装则在 `~/.agy-delegate/runs/`，也可用环境变量 `AGY_RUNS_DIR` 指定。每个运行一个目录：`prompt.txt`、`events.ndjson`（agy 全量事件）、`digest.log`（人读摘要）、`final.txt`、`result.json`（结构化结果）、`meta.json`、`agy.log`。**不会自动清**，试验性的运行做完后手工删。
- 运行器进程不管怎么死（含被强杀），系统都会通过 Job Object 把 agy 及其后代带走；记录里的 `state=running` 但运行器已不在的，`list` 会显示为 `ORPHANED`。

## 11. 适配层：让新的主代理自己补全

运行器和本文是通用的。**主代理各自的能力不同**（能不能后台跑长命令并被输出唤醒？有没有通知用户的办法？能不能给用户开一个实时窗口？），这些差异放在 `adapters/<代理名>.md` 里。

**现有适配层**（新增一份就在这里加一行）：

| 文件 | 适用的主代理 |
|---|---|
| `adapters/claude-code.md` | Claude Code（含桌面端） |

### 如果你在 `adapters/` 里找不到自己的适配层

不要硬套别家的适配层，也不要凭感觉用。按下面的规程做，做完以后下一次（以及别的同类代理）就不用再补：

1. **确认没有**：`adapters/` 里有没有以你的代理名命名的文件（`claude-code.md`、`codex.md`…）。有就读它、照做，到此为止。
2. **盘点自己的能力**，诚实回答这四个问题（不确定的当作"没有"）：
   - **A. 后台长命令 + 输出唤醒**：我能不能启动一条长时间命令，并且它每输出一行我就被唤醒？有 → 模式 A；没有 → 模式 B。
   - **B. 主动通知用户**：我有没有工具能在我不说话的时候让用户看到消息（桌面通知、聊天推送）？没有 → 用 `--notify-cmd`；连命令也没有合适的 → 只能在回复里明确转告。
   - **C. 给用户开实时窗口**：我能不能为用户打开一个终端标签/窗口跑 `watch`？不能 → 把 `watch` 的完整命令写进回复，让用户自己开。
   - **D. 验收工具**：我能不能读文件、跑测试、看 `git diff`？不能 → 这套流程不适合你，告诉用户并停止。
3. **跑环境自检**：
   - `<RUNNER> selftest`（零 token）。全部 `OK` 才继续。
   - 再做一次**真实小任务自检**。它会花很少一点额度，而且要 1～2 分钟（agy 启动要等 MCP 服务器）。**先在回复里告诉用户**；没有对话渠道的，就写进适配层的"走通记录"。方式二选一：
     - 你的单次命令能等 3 分钟以上：`<RUNNER> selftest --live`（前台跑，看 `真实小任务端到端` 一行是否 OK）。
     - **单次命令上限不足 3 分钟（多数模式 B 的代理）必须用 `<RUNNER> selftest --live --detach`**：拿到 `STARTED run=<运行名>` 后，用 `wait <运行名> --until end --timeout <小于你单次上限的秒数>` 反复等到 END（返回码 11 就再调一次），`verdict=DONE_UNVERIFIED` 才算通过。**不要前台硬跑**：被你的工具超时打断会连带杀掉运行器，留下 `ORPHANED` 记录。
   - 自检失败不要硬重试：503 / 容量不足就等一分钟再试一次；其余原因写进适配层的"踩到的坑"，并告诉用户。
4. **写适配层**：复制 `adapters/_template.md` 为 `adapters/<你的代理名>.md`，逐节填写：确切的启动命令、怎么等事件、每类告警你怎么处理、怎么通知用户、怎么给用户实时窗口、你踩到的坑。**只写"怎么用"，不要改运行器、不要改本文的规则。**
5. **走通一遍再宣布完成**：第 3 步的真实小任务自检本身就是一个最小任务，**不必再多跑一个**。这一步只需要按你写的适配层把关键动作再走一遍：读到 `END` 和 `result.json`；模式 B 在 `selftest --live --detach` 刚返回时，立刻调一次 `wait <运行名> --timeout 5`，应当收到 `WAIT_TIMEOUT`（返回码 11）；模式 A 确认事件行真的能唤醒你。
6. **登记并告诉用户**：在上面"现有适配层"表里追加一行（这是唯一允许的对本文的改动）；告诉用户适配层已经创建、选了哪种模式、哪些能力缺失（比如没有主动通知）以及因此哪些事需要用户自己盯。
7. **不能做的事**：不改 `agy_run.py`；不碰 agy 的设置和登录凭据；不用 `agy update`、`/logout`、`/login`；换账号只能用户做。

## 12. 模型与额度

- 默认且推荐 `gemini-3.8-flash-high`（需要判断的任务）；纯机械活可以 `--effort low`。可用模型用 `agy models` 查；要换成别的模型，先告诉用户，由用户决定。
- Claude/GPT 那组额度较少，除非用户点名，否则不用。
- 额度桶：`gemini-5h`（5 小时窗口）、`gemini-weekly`、`3p-5h`、`3p-weekly`。粗略换算：100 万个代价单位（输入 + 6×输出 + 0.1×缓存读）约等于 5h 桶 −3.4 个百分点、周桶 −1 个百分点；一个小任务只耗 5h 桶 0.2～0.6 个百分点，**长任务（上下文累积）才是大头**。
- 启动前预检下限 5%，只是粗筛；长任务开跑前自己估一下余量。运行中额度耗尽会 `ALERT QUOTA`，带上"额度重置于 …"。
- 并发的运行共享同一个账号，`END` 里的额度前后差值在并发时**不可归因**到单个运行。

## 13. 约束

- 默认串行；并行只在任务互不依赖、且各自在独立 worktree 时使用。
- 大任务先用 `--plan` 让 agy 出方案，调用方审过后再分阶段执行。
- 不要让 agy 启动需要在它退出后继续存活的进程；要给用户起本地应用或开发服务器，由调用方在用户的终端里启动。
- agy 改文件期间，提醒用户不要对同一工作区里正在运行的应用做热重载。
- 换账号只能由用户在交互界面完成；调用方不碰 agy 的登录凭据。
- **不要把 `agy` 当 shell 命令直接敲**：在 Git Bash 下 `agy -p "/usage"` 会被改写成 `<Git 安装目录>/usage` 并真的发给模型。查额度用 `<RUNNER> quota`。
- agy 的全局技能只认 `~/.gemini/skills`。
